Hello Miro team,

I'm looking for a product where the number of things users can make keeps growing and design has to keep them findable. Miro's canvas is that product. At Northwind Analytics I've spent three years on a reporting suite that gained a new report type every few weeks, and I currently own the pattern each new type has to fit. The job is mostly saying no kindly, and writing down why.

Owning that pattern taught me where growth hurts first, so I looked for the same spot in your product. It is the toolbar, which I found by watching how people add one more object to a board.

One challenge I worked through

A person on a board reaches for a less common object. The toolbar shows a short row of frequent tools, then a longer menu, then a search. New object types land in the menu, so this week's most useful tool sits beside one used once a year.

Source: public help page on the toolbar and object menu [verify]

The example is from my current team at Northwind, where the growth pressure looks the same.

At Miro

  • New object types join one long menu
  • Frequency of use and position in the list are unrelated

At Northwind Analytics

  • New report types joined one long menu at Northwind
  • A fixed set of six patterns decided where each new type went
What I did about it
→

At Northwind those six patterns became the review gate for every new report type. The rule was written down once, and two reports shipped through it after I moved teams, built by other designers without my review (a count of what I saw, not a controlled measure).

From the outside I can only see the surface, so this is a guess about the inside.

You have constraints I cannot see: performance on large boards, a long tail of older tools, a team that has lived with this for years. Within those, I would enjoy the argument about where the next object type belongs and what the toolbar refuses to show. I can walk you through the six patterns and the cases we rejected.

Happy to talk it through.
